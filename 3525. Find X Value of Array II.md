# Problem Statement

You are given:

- An array of positive integers `nums`.
- A positive integer `k`.
- A list of queries.

Each query is:

    [index, value, start, x]

For every query:

1. Update `nums[index] = value`.
2. This update **persists** for all future queries.
3. Remove the prefix `nums[0 ... start - 1]`.
4. Then we may remove any suffix, including an empty suffix.
5. Count the number of ways such that the product of the remaining non-empty array has remainder `x` modulo `k`.

Return the answer for every query.

---

## Important Observation

After removing the prefix up to `start - 1`, the remaining array is:

    nums[start ... n-1]

We can then remove a suffix.

Therefore, every possible remaining array is exactly a **non-empty prefix** of:

    nums[start ... n-1]

For example:

    nums = [1,2,3,4,5]
    start = 2

The remaining array is:

    [3,4,5]

Possible non-empty arrays after removing a suffix are:

    [3]
    [3,4]
    [3,4,5]

So the query asks:

> Among all non-empty prefixes of `nums[start ... n-1]`, how many have product remainder `x` modulo `k`?

The difficulty is that every query can also modify one element.

Since:

    n <= 10^5
    queries <= 2 * 10^4
    k <= 5

we need a data structure that supports:

- Point update.
- Query all prefix-product remainders in a range.

A **segment tree** is ideal for this.

---

## Segment Tree Idea

For every segment, store two things:

### 1. `prod`

The product of all elements in the segment modulo `k`.

### 2. `pref[r]`

The number of non-empty prefixes of this segment whose product has remainder `r`.

For example, suppose a segment contains:

    [2, 3, 4]

and:

    k = 5

Its non-empty prefixes are:

    [2]       -> 2
    [2,3]     -> 6 % 5 = 1
    [2,3,4]   -> 24 % 5 = 4

Therefore:

    pref[1] = 1
    pref[2] = 1
    pref[4] = 1

and:

    prod = 4

---

## Merging Two Segments

Suppose we have two adjacent segments:

    A | B

Assume:

    A.prod
    A.pref[]
    B.prod
    B.pref[]

The total product is:

    (A.prod * B.prod) % k

Now consider the prefixes of `A + B`.

There are two types.

### Type 1: Prefix Ends Inside A

These prefixes are exactly the prefixes already stored in `A`.

So:

    result.pref[r] += A.pref[r]

### Type 2: Prefix Contains All of A and Some Prefix of B

If a prefix of `B` has product remainder `r`, then after adding all of `A`, its new remainder becomes:

    (A.prod * r) % k

Therefore:

    result.pref[(A.prod * r) % k] += B.pref[r]

This allows us to merge two segment-tree nodes in `O(k)` time.

---

## Example of Merge

Suppose:

    A = [2]
    B = [3,4]

with:

    k = 5

For `A`:

    prod = 2
    pref[2] = 1

For `B`:

    prefixes:
    [3]     -> 3
    [3,4]   -> 12 % 5 = 2

So:

    B.prod = 2
    B.pref[3] = 1
    B.pref[2] = 1

Now merge them.

Prefixes from `A`:

    [2] -> 2

Prefixes using all of `A` plus a prefix of `B`:

    2 * 3 % 5 = 1
    2 * 2 % 5 = 4

Therefore the combined segment `[2,3,4]` has:

    [2]       -> 2
    [2,3]     -> 1
    [2,3,4]   -> 4

Exactly as required.

---

## Range Query

For a query:

    [index, value, start, x]

we first update:

    nums[index] = value

Then query the segment tree for:

    [start, n - 1]

The resulting node contains:

    pref[x]

which is exactly the number of valid ways for this query.
